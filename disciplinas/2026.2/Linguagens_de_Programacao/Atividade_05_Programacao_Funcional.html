Programação funcional

Aprenda passo a passo. Primeiro observe os dados; depois experimente operações; por fim, conecte o que viu aos conceitos do paradigma funcional. Não é necessário saber uma linguagem específica para começar.

O problema

Contexto: Uma professora quer entender o desempenho da turma

Ela possui estas notas e quer responder perguntas simples: quem atingiu 7,0? Qual seria o dobro de cada nota? Qual é a média?

A coleção de partida será chamada de notas. Vamos preservar seus valores originais durante as demonstrações.

1. Três operações, três objetivos

Cada operação resolve um tipo diferente de problema.

FILTRAR

Selecionar

Queremos apenas as notas maiores ou iguais a 7,0. A pergunta é: “este valor atende à condição?”

MAPEAR

Transformar

Queremos o dobro de cada nota. A regra será aplicada a cada elemento.

AGREGAR

Resumir

Queremos um único valor que resuma a coleção: soma e média.

Clique em uma operação para ver o resultado.
Como lembrar a diferença?
OperaçãoPerguntaResultado
FiltragemQuais elementos atendem a uma condição?Uma coleção menor ou igual à original.
MapeamentoO que resulta ao transformar cada elemento?Uma coleção com um resultado para cada elemento original.
AgregaçãoQual é o total ou resumo dos valores?Um valor, como soma ou média.

2. Visualizando o caminho dos dados

Na programação funcional, podemos pensar em uma coleção passando por uma operação, que produz um resultado.

→

Importante: esse é um modelo mental. Nem toda operação funcional retorna uma coleção; uma soma, por exemplo, retorna um único número.

3. O que significa "função como argumento"?

Uma função de ordem superior é uma função que recebe outra função como argumento ou retorna uma função. Neste exemplo, vamos focar na primeira ideia.

Operação map
+
Regra: “multiplicar por 2”
→
Dobro de cada nota

O map não precisa saber por que escolhemos multiplicar por 2. Ele aplica a regra recebida a cada elemento.

Exemplo sem sintaxe de linguagem:
Dados: 4,0; 7,5; 8,0
Regra fornecida: multiplicar por 2
Resultado: 8,0; 15,0; 16,0
E no caso de filtragem?

A operação de filtragem recebe uma regra que responde “sim” ou “não” para cada elemento. Por exemplo: “a nota é maior ou igual a 7,0?”. Se a resposta for sim, o valor é mantido no resultado.

4. Imutabilidade: preservar os dados originais

Imagine que você precise da lista original para calcular a média e, ao mesmo tempo, de uma lista com notas dobradas. Se alterar a lista original, poderá perder os valores necessários para outras análises.

Antes

Notas originais

4,07,58,0
Transformação

Aplicar a regra

Multiplicar cada nota por 2.

Depois

Dois conjuntos de dados

Os valores originais continuam disponíveis; os dobrados formam um resultado separado.

Imutabilidade é a ideia de não alterar um dado depois de criado. Em uma abordagem funcional, preferimos produzir novos resultados a modificar os dados de partida.

5. Funções puras: mesma entrada, mesmo resultado

Considere a função dobro, que recebe um número e retorna o número multiplicado por 2.

Entrada: 8
→
dobro
→
Saída: 16

Se chamarmos a função novamente com a entrada 8, o resultado será 16 outra vez. A função não precisa ler ou alterar uma variável externa.

Chamamos essa função de pura quando, além de retornar sempre o mesmo resultado para a mesma entrada, ela não produz efeitos colaterais observáveis.

Qual seria um exemplo de efeito colateral?

Uma função que, além de calcular, altera uma variável global, grava um arquivo ou exibe uma mensagem na tela produz um efeito além de simplesmente retornar um valor. A entrada/saída é útil, mas é diferente de uma função pura.

6. Veja os mesmos conceitos em linguagens diferentes

As ideias da programação funcional podem aparecer em linguagens com sintaxes distintas. Compare os exemplos:

Python

Filtragem e mapeamento

notas = [4.0, 7.5, 8.0, 5.5, 9.0, 6.0, 3.5]

aprovacao = list(filter(lambda n: n >= 7.0, notas))
dobradas = list(map(lambda n: n * 2, notas))

print(aprovacao)  #[7.5, 8.0, 9.0]
print(dobradas)   #[8.0, 15.0, 16.0, 11.0, 18.0, 12.0, 7.0]

Como ler: filter recebe a condição n >= 7.0. map recebe a transformação n * 2. Em ambos, a regra é passada como argumento.

Existe uma forma mais legível em Python? 
aprovacao = [n for n in notas if n >= 7.0]
dobradas = [n * 2 for n in notas]

Sim. As compreensões de lista são uma forma comum e clara de expressar essas operações em Python. Elas não alteram a lista original neste exemplo.

Haskell

Filtragem e mapeamento

notas = [4.0, 7.5, 8.0, 5.5, 9.0, 6.0, 3.5]

aprovacao = filter (\\n -> n >= 7.0) notas
dobradas = map (\\n -> n * 2) notas

main = do
  print aprovacao
  print dobradas

Como ler: \\n -> n * 2 descreve uma função anônima: recebe um valor chamado n e retorna o dobro. Em Haskell, listas e expressões funcionais são parte central da linguagem.

Pseudocódigo

A ideia sem depender da sintaxe

aprovacao ← FILTRAR(notas, nota ≥ 7,0)
dobradas  ← MAPEAR(notas, nota × 2)
total     ← SOMAR(notas)
media     ← total / quantidade(notas)

O pseudocódigo destaca o raciocínio. A linguagem escolhida determina a sintaxe concreta.

O que os exemplos têm em comum?
  • Filtragem seleciona elementos conforme uma condição.
  • Mapeamento aplica uma transformação a cada elemento.
  • A regra é fornecida à operação como uma função ou expressão funcional.
  • Os exemplos criam resultados separados e preservam a coleção original.
